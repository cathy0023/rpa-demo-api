# 企微侧边栏·智能销售话术助手（场景化实时生成）

## 背景

- **来源**：用户需求（2026-09-02），智能销售话术助手产品要把话术生成能力集成到企业微信聊天工具栏（侧边栏），让销售在与客户聊天时实时获取 AI 生成的个性化话术。
- **现状**：
  - sop-mini 已有 RPA demo 全闭环（`docs/rfcs/inbox/2026-08-26-rpa-demo.md`）：客户消息 → 回调验签解密 → LLM 话术生成（`llm.py` / `generate_reply`）→ 落库 → 回发。话术生成能力可直接复用。
  - 后端 FastAPI（`rpa-demo-api/`），前端 React19+TS+Vite（`rpa-demo-web/`）。
- **痛点**：销售在企微里跟客户聊天时，话术生成能力不在现场——需要切到别的工具去问 AI，没有客户上下文，生成的话术不贴场景。企微侧边栏是「话术出现在销售工作现场」的唯一合规入口。
- **平台调研结论**（2026-09-02）：
  - 形态：自建应用的 H5 页面配置到「聊天工具栏」，销售在**与客户单聊/客户群**里点开，右侧弹出侧边栏（工具栏数量上限 50 个，官方建议 ≤8）。
  - 会话上下文专用接口：`wx.qy.getCurExternalContact` 拿当前客户 userid → 服务端调 `/cgi-bin/externalcontact/get` 拉客户详情（头像/备注/标签等）。前提：先 `wx.qy.login`、成员在应用可见范围内。
  - 鉴权链路：服务端获取 `jsapi_ticket` → 生成签名 → 前端 `wx.config` 初始化；企微管理后台需配置「网页授权及JS-SDK 可信域名」。
  - **关键限制**：侧边栏页面**读不到实时聊天记录原文**；聊天上下文需走「会话存档」（msgaudit）接口——需企业购买 + 合规审批 + RSA 密钥配置，是本需求最大的外部依赖。
  - 配置侧边栏页面后需**重启企业微信**才生效（有缓存）。
  - 竞品形态：卫瓴小微AI（画像+聊天记录生成个性化话术）、纷享销客（知识库+优秀话术库推荐）、探迹（素材库一键调用）、句子互动（AI 员工按结果付费）。

## 目标（用户视角）

- 销售在与客户单聊中打开侧边栏，**自动识别当前客户**，无需手动搜索。
- 侧边栏自动注入**客户画像**（企微外部联系人资料/标签）与**历史聊天上下文**（会话存档），AI 基于真实场景**实时生成 1 条贴合的话术**，支持「换一条」重生。
- 销售一键复制话术，回聊天框粘贴发送（不直接代发）。
- 全链路技术闭环可演示：打开侧边栏 → wx.config 成功 → 拿到客户 userid → 拉画像+历史 → LLM 生成 → 展示可复制话术。
- 架构按**先自建应用验证、后升级 SaaS（服务商代开发）**演进预留，验证期不投入 SaaS 化复杂度。

## 范围

### 在范围内（In Scope）
- 企微自建应用 + 侧边栏 H5（前端新页面，JS-SDK 鉴权：jsapi_ticket 签名 / wx.config / wx.qy.login / getCurExternalContact）
- 会话存档（msgaudit）接入：RSA 密钥配置、消息拉取、解密、落本地存储（上下文策略：**实时拉取 + 本地存储**，侧边栏打开时 SQL 查该客户最近 N 条）
- 客户画像代理接口（服务端封装 externalcontact/get，前端不持有企微 secret）
- 话术生成 API（复用 `llm.py`，输入 = 客户画像 + 历史聊天摘要 + 场景，输出 = 1 条话术；重生 = 重新生成）
- 本地存储（延续 SQLite 路线：会话存档消息、客户资料缓存、生成记录）
- 配置走环境变量 + 配置文件（企微 corp_id / agent_id / secret / 会话存档 key 等）

### 不在范围内（Non-Goals）
- 群聊场景（客户群侧边栏，需额外接口）
- 一键发送话术到会话（JS-SDK shareToExternalChat，权限审核复杂；MVP 用复制粘贴）
- 管理后台（话术风格/知识库/产品资料的配置界面，先用 prompt 模板 + 配置文件）
- 销售使用数据统计（采纳率/转化率回流）
- SaaS 多租户/服务商代开发上架（验证后再升级）
- RPA 主动外呼等既有 demo 能力的整合（保持独立演进）

## 约束

- 技术栈延续 sop-mini 现有栈：后端 **Python (FastAPI)**，前端 **React**；密钥**绝不入库**，只走环境变量/配置文件。
- LLM 沿用 **OpenAI 兼容直连**（httpx），不引入新 LLM 中间层（LiteLLM 等）。
- 侧边栏 H5 必须企微内可访问：**可信域名 + HTTPS**；验证期用内网域名即可，SaaS 化时再上公网域名。
- 会话存档属敏感合规能力：消息数据仅本地存储用于话术生成，不做转发/导出。
- 无明确 deadline，验证期以跑通价值为先。

## 已讨论的方案

### 方案 C：会话存档深度方案（已选 ✓）
- **核心思路**：把企微会话存档（msgaudit）作为一等公民——RSA 密钥接入 + 消息实时拉取落本地 SQLite + 侧边栏打开时拼「客户画像 + 最近 N 条聊天」作为 LLM 上下文，实时生成话术。上下文策略选 **A：实时拉取 + 本地存储**。
- **优点**：
  - AI 上下文最强（真实聊天记录 + 画像），最接近卫瓴形态，生成质量天花板最高
  - 会话数据自有落库，为后续 SOP 阶段判断、话术效果回流留了地基
- **缺点**：
  - 强依赖企业购买会话存档 + 合规审批（**开通状态未知，最大风险**）
  - 需维护消息同步/解密/落库链路，工作量最大（大）
- **工作量**：大

### 方案 A：扩展现有 rpa-demo-api（已讨论未选）
- **核心思路**：在现有 FastAPI 服务里新增企微侧边栏模块（jsapi_ticket 签名、客户资料代理、话术生成 API），前端新建独立 sidebar-web H5；历史上下文先用 demo 库里 RPA 会话数据。
- **优点**：复用 llm/config/db，落地最快（小工作量）
- **缺点**：无真实聊天上下文，AI 生成质量受限；demo 与产品能力耦合，SaaS 化时要拆
- **驳回理由**：用户明确要「历史聊天记录上下文」作为核心输入维度，A 方案用 RPA demo 数据替代会话存档无法达成该目标。

### 方案 B：独立 sidebar 服务（已讨论未选）
- **核心思路**：新建独立 sidebar-api FastAPI 服务（抽包复用 llm 等模块），前端独立 H5，天然多租户-ready。
- **优点**：边界干净，SaaS 升级不用拆
- **缺点**：前期重复建设、两个服务运维，验证期投入偏重
- **驳回理由**：验证期优先跑通价值而非架构纯洁性；可作为 SaaS 化阶段的演进形态（届时从 C 方案的代码中拆出）。

## 成功标准

- [ ] 企微管理后台完成：自建应用创建、可信域名配置、侧边栏页面配置、应用可见范围设置
- [ ] 销售在与客户单聊中打开侧边栏：`wx.config` 鉴权成功 → `wx.qy.login` 登录态有效 → `getCurExternalContact` 返回当前客户 userid
- [ ] 服务端用 userid 拉到客户画像（`externalcontact/get`：昵称/备注/标签等）
- [ ] 会话存档链路跑通：RSA 密钥配置 → 消息拉取 → 解密 → 落本地库 → 可按客户查询最近 N 条
- [ ] 侧边栏展示 1 条基于「画像 + 历史」的 AI 话术，可一键复制；点「换一条」可重新生成
- [ ] 全链路无手动干预（销售除复制粘贴外零输入），端到端演示可重复
- [ ] 密钥（企微 secret / 会话存档 key / LLM key）全部走环境变量，不入库
